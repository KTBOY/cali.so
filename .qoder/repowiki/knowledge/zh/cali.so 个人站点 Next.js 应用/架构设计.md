- 入口由 `next.config.mjs` 在构建/启动时按需 `import('./env.mjs')` 加载环境变量，并通过 Zod 在服务端与客户端分别校验 server/client 两类变量，禁止客户端访问服务端变量。
- `middleware.ts` 作为全站请求入口：先通过 Vercel Edge Config 拉取黑名单 IP 做拦截，再根据地理信息写入 Upstash Redis（键来自 `~/config/kv`），最后交由 `@clerk/nextjs` 的 `authMiddleware` 按 `publicRoutes` 白名单放行。
- 运行时依赖通过根 `package.json` 集中声明，`pnpm-workspace.yaml` 为空数组表示当前为单包结构；`turbo.json` 仅对 `dev/build/lint` 定义缓存策略，配合 `next dev --turbo` 使用。
- 外部服务连接点集中在根级配置：`drizzle.config.ts` 指向 `db/schema.ts` + `DATABASE_URL`，`sanity.config.ts` 挂载 `/studio` 并引入 `~/sanity/plugins/settings`，`next.config.mjs` 允许 `cdn.sanity.io` 图片域名。
- 子模块通过 `~/` 路径别名被统一消费：`shared_components` 提供页面级 UI，`config_and_lib` 暴露 `kvKeys`、`redis`、`email` 等单例，`database` 暴露 Drizzle schema 与查询，`emails` 以 React 组件形式渲染，`sanity_cms` 提供 Groq 查询与 Studio 插件。
