模块按职责分层组织：
- `env.ts` 集中导出 `apiVersion`、`dataset`、`projectId`、`useCdn` 等运行时配置，并通过 `assertValue` 在启动时校验必填环境变量；`lib/client.ts` 基于 `next-sanity` 的 `createClient` 使用这些配置创建单例 client。
- `schemas/` 下每个文档类型一个文件（post、category、project、settings、blockContent），通过 `defineType` + `defineField` 声明 Sanity schema，并同步用 Zod 导出 TypeScript 类型（如 `Post`、`PostDetail`）供上层消费；`schemas/types/readingTime.ts` 是自定义输入类型的复用单元。
- `schema.ts` 作为聚合入口，将所有 type 注册到 `{ types }` 结构体中，供 Sanity Studio 加载。
- `plugins/settings.ts` 通过 `definePlugin` 隐藏 singleton 类型的“新建/重复”操作，并用 `StructureResolver` 将 Settings 文档挂载到 DeskTool 根目录首位，实现单例管理。
- `queries.ts` 以 `groq` tagged template 编写查询，每份 Groq 模板配套一个同名的 `client.fetch<T>()` 包装函数，统一返回 Promise，屏蔽底层 fetch 细节。
- `components/` 提供 Sanity Studio 侧的自定义组件（ReadingTimeInput、Tweet），`lib/image.ts` 封装图片 URL 处理逻辑，均仅被 Studio 或渲染层消费，不反向依赖 schemas。
依赖方向：`queries.ts` → `lib/client.ts` → `env.ts`；`schema.ts` 聚合所有 `schemas/*`；`plugins/*` 独立注入 Studio 行为。
